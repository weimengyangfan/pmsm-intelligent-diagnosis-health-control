# 电流哨兵 R2：把过程和对照讲清楚

这次只更新上位机。沿用已经下载成功、带 RAW_HOST V1 标识的F407固件、FPGA启动镜像、板端服务和NPU模型。无需打开Keil、Vivado，也无需上传新的板端脚本。

本版交付的是新的连续情景与对照流程。开发端已验证代码、积分、封包和界面流程；新情景的实板表现要以你接下来导出的记录为准。

## 现在怎么运行

1. Windows：把整个ZIP解压到一个新文件夹，保留R1目录。关闭旧上位机和占用COM5的串口助手。
2. Windows：双击 `desktop/start.cmd`。填写F4串口COM5、FPGA地址192.168.126.49、root密码，点击连接。依赖与旧版相同。
3. 等待F4固件与板端服务就绪。在默认的“一键对照实验”页点击“完整情景演示”。预计约3～4分钟，期间不用反复点击。
4. 看三张卡：回放设定、本次NPU实测、三周期确认规则。卡片下方显示F4/PC积分校核与最近中心基线。波形下半部把采样误差单独放大；窗口较小时可滚动。
5. 结束后点击“导出报告与原始记录”。同目录得到JSON原始记录、HTML可视报告、`_feedback_requests.json`待执行反馈请求。用浏览器打开HTML查看，再保留JSON供复核。

只需要先跑这一次21周期完整情景。17类核对和51次扰动对照是后续可选项目，不必一开始把所有测试重跑。

若CMD显示缺依赖，在Windows CMD进入本包的desktop目录，运行：

```bat
py -3 -m pip install -r requirements.txt
py -3 demo_dashboard.py
```

若日志明确出现 `BlockingIOError: [Errno 11] Resource temporarily unavailable`，说明旧的同名板端服务仍占锁。在MobaXterm的 **FPGA root终端** 执行：

```sh
pkill -TERM -f 'motor_monitor_service[.]py'
pgrep -af 'motor_monitor_service[.]py'
```

第二条无输出后重新连接上位机。不需要删除锁文件或重新下载固件。若提示串口占用，关闭旧上位机/串口助手后再连接。未知或变化的SSH主机密钥仍需先用Windows原有SSH核对，程序不会忽略主机密钥检查。

## 一次演示展示什么

| 对照 | 数据和算法 | 观众能看到什么 |
|---|---|---|
| 健康参考 / 偏移采样 | 原MAT中保存的相邻电角周期，离线叠加诊断通道偏移 | 波形整体偏高/偏低；放大的差值显示偏移量 |
| PC黄金积分 / F4实算 | 同一批FP32时间、电流点，按时间做梯形积分 | F4实际算出的B/C均值、误差与校核门限 |
| 最近中心基线 / NPU分类 | 两者使用同一组实收F4均值；基线在PC，NPU在板端 | 每个周期的两种分类和实测标签符合率 |
| 单次报警 / 三周期确认 | 同一批NPU实测分类；两种规则均在PC | 短暂偏移与持续偏移如何产生不同的报警过程 |
| 模型结构 / 当前计算结果 | 本地编译文件证据与匹配序号的板端输出 | 三层网络、ZG330算子清单、当前17个实际logits |

最近中心基线可能与NPU同样准确。本版不预设NPU准确率或速度优于基线。当前二特征任务比较简单，NPU部分展示的是模型映射、量化部署和实际硬件推理链路。

## 连续情景与报警口径

21个周期来自同一段相邻的原仿真波形，并非重复同一个特征向量：

| 周期 | 回放设定 | 要观察的行为 |
|---|---|---|
| 1～3 | 正常 | 建立基线 |
| 4 | 短暂B相+0.2A偏移 | 单次规则可能报警，三周期规则应等待 |
| 5～7 | 正常 | 短暂异常未持续 |
| 8～11 | 持续B相+0.2A偏移 | 连续有效且同相同方向分类达到3次后确认 |
| 12～14 | 正常 | 连续3个正常周期确认恢复 |
| 15～18 | 持续C相-0.5A偏移 | 验证另一相和另一方向 |
| 19～21 | 正常 | 再次确认恢复 |

上表是测试设定和期望行为，不是已经发生的实板结果。界面与报告只使用实际回传的分类。有效但分错的结果会继续计入对照，不能因不符合标签就提前筛掉；无效结果、丢帧或超时会中止本次连续实验。无效数据不代表恢复正常，已有报警保持。

确认规则按B+/B-/C+/C-分组，幅值从+0.1变到+0.2仍可累计同一组；类别档位仍逐周期保留。首个报警后，连续3个正常结果才清除。单次对照使用1周期确认与1周期恢复。

**相邻的是仿真源时间，硬件回放在现实中是逐点握手、分批运行。** 每个仿真周期约8.219ms，现实处理一个周期约需数秒；三周期确认不能宣传成现实中约25ms的报警。NPU推理/读取耗时与完整上传往返耗时分别计量。

## NPU、算子和分工

- PC：电角度分周期、回放调度、黄金积分校核、最近中心基线、报警确认、记录与展示。
- F407：接收原始时间/电流点，验证CRC、顺序和时间，积分求B/C均值；通过校核后用自身计算值封装SPI包。
- FPGA：SPI接收与跨时钟快照。Linux：标准化、NPU调度与Argmax。
- 厂家ZG330 NPU：执行2→16→16→17分类网络。609个逻辑参数，560次逻辑MAC；编译文件中11个HardOp，包含3个Conv2dNode。物理补齐、转换开销不能用逻辑MAC数代替。

“NPU计算”页分开显示静态编译证据和当前17个实测logits；logits不是概率，页面不伪造隐藏层活动或逐算子计时。厂家NPU核不是我们自行设计的核。

## 反馈阶段现在到哪里

真实NPU结果达到三周期确认后，导出与run_id、序号、原仿真时间绑定的停机请求，字段 `executed=false`。这只是反馈接口的数据，**还没有运行Simulink反馈，也没有验证闭环控制响应**。

后续必须在模型副本中，使用这次实际产生的请求，记录命令、转速和电流的响应，与同条件无反馈运行对照后，才能补上“诊断→决策→仿真响应”。不要预画一条降速曲线当作执行结果。

本包的 `matlab/inspect_feedback_ports.m` 仅用于下一阶段读取模型命令入口和输出记录项，不改线、不仿真、不操作实物。你当前模型里的入口名称是CMD_RPM，不能仅凭之前口头讨论就当成Iq接口。进一步安排见 `docs/方案与验收.md`。

## 数据范围

原文件：motor_bias_raw.mat，SHA256为e9c6bb31f77b3a81e79d4f8cbbff3e3350063e1ec9f4db76892d36d67a273d5f。使用原仿真0.9～1.3s稳定段；诊断偏移没有进入FOC控制回路。完整21周期情景覆盖原仿真约0.904～1.076s。

这不是F4 ADC实时采集，不是实时硬件在环，不是已经验证的真实电机故障诊断。R2的受控重构属于功能验证，不是独立外部泛化测试集。

51次可选扰动对照使用相同17个周期，叠加0、±0.01、±0.03A范围内的固定随机均值偏移，随机种子20261101。它既不是51次独立仿真，也不是ADC时域随机噪声实验。
