# 电流哨兵 R4.0.0：非实时实板诊断与模型联动

这一版的目标：**本轮 Simulink 电流 → 真实 F4 积分 → SPI/FPGA → 真实 NPU 分类 → 板端连续三周期确认 → PC 转交结果 → 模型参考下降 → 新电流再次诊断。**

现在交付的是待现场验证的软件包。没有在本地执行 MATLAB 或连接用户板卡；不能将软件测试结果称为闭环实验成功。现有 R2/R3 版本继续保留。

## 本版边界

- 不重新训练模型，不修改 FPGA RTL、位流或 F4 固件。
- 需要现有 F4 固件打印 `RAW_HOST V1`，也就是此前完成原始波形积分测试的固件。
- 板端原有 `/root/motor_ai/motor_monitor_service.py` 和模型继续使用；新增包装程序启动它，读取真实推理输出。原服务文件不覆盖。
- 三周期确认在**板端 Linux**执行。输入标签不参与决策。
- 返回路径是 **SSH → 电脑桥接 → Simulink**。没有声称 SPI 返回诊断请求、MCU执行降参考或 MCU执行确认已经完成。
- 仿真每段停止，等待实板处理后续跑；模型时间与现实等待时间分开记录。不是实时硬件在环，也没有控制实际电机。
- 偏移只在诊断支路注入；FOC控制电流仍是原始健康电流。不能据此宣称已验证控制反馈传感器发生故障时的鲁棒性。

## 第一步：只验证 MATLAB 状态续接（现在先做这一步）

将 ZIP 解压到 `C:\FPGA\FPGAq\motor\`，得到：

`C:\FPGA\FPGAq\motor\motor_link_r4\`

在此前能运行 R3 的 MATLAB R2020b 环境中操作，保留原电机工程的初始化参数。此步不需要板卡、不占用串口。

```matlab
addpath('C:\FPGA\FPGAq\motor\motor_link_r4\matlab');
prepare_motor_link_r4;
```

弹窗中选择**原来零偏移基线使用的、已保存的原模型**，例如 `FOC_LADRC_G474_bias_isolated_v2.slx`。不要选择 results 下的 R3 模型。若原模型有未保存修改，先 Ctrl+S；脚本会新建 R4 模型副本，不覆盖原模型。

然后执行：

```matlab
check_motor_link_r4;
```

它检查两件关键事情：

1. 连续运行与分段保存/恢复完整 operating point，转速、电流和角度是否一致。
2. 恢复状态后，只修改未来的参考输入，是否与一次连续运行相同；过去轨迹是否保持不变。

通过应打印 `R4_PREFLIGHT_PASS`。固定时刻的降参考仅用于本阶段的软件等价性测试，**不是后面正式实板实验的报警时刻**。

结果在 `motor_link_r4\preflight\status.json` 与 `continuation_check.mat`。若报错，先停止此阶段，把完整报错和 status.json 发回检查；不要跳过检查继续板卡实验。

`settings.json` 会持久保存选定模型、模型哈希和实验设置。后续不需要重新输入 modelPath 等临时变量。原模型依赖的工程初始化参数仍由原工程管理，本包不会替你猜电机参数。

## 第二步：安装新增板端程序（仅第一步通过后）

先关闭旧上位机和串口助手。旧上位机正常退出后，应该释放串口和它启动的服务。

在 Windows CMD 执行（不是在 Linux 提示符下）：

```bat
scp -O "C:\FPGA\FPGAq\motor\motor_link_r4\board\r4_policy.py" "C:\FPGA\FPGAq\motor\motor_link_r4\board\motor_link_service_r4.py" root@192.168.126.49:/root/motor_ai/
```

只增加两个文件，不覆盖原服务和模型。无需下载固件、改 BOOT.bin 或改 SD 卡。

如果 SSH 提示主机未知，先在 CMD 执行 `ssh root@192.168.126.49`，核对主机密钥后正常退出。桥接程序拒绝未知或已改变的主机密钥。

若板端提示锁被占用，在另一个 Linux 终端只读查看：

```bash
pgrep -af 'motor_monitor_service[.]py|motor_link_service_r4[.]py'
```

先退出启动旧服务的那个程序；不要删除锁文件或反复启动多个接收程序。必要时根据查到的 PID 定向结束确认属于旧演示的进程。

## 第三步：启动电脑桥接

电脑需已有 Python、pyserial、paramiko；此前上位机已使用这些库。缺依赖时再双击 `install_pc_dependencies.cmd`。

双击 `start_bridge.cmd`：

1. 输入 F4 串口，默认 COM5。
2. 输入 FPGA 地址，默认 192.168.126.49。
3. 输入 root 密码（输入时不显示，程序不保存密码）。

等待 `R4_BRIDGE_READY`。这表示识别到原始积分固件，且板端原服务已发出就绪事件。它并不代表完整实验已通过。

桥接日志在 `runtime\bridge.log`，请求与返回记录在 `runtime\inbox`、`runtime\outbox`。每次启动有独立会话标识，旧返回文件不会当作本轮结果。

## 第四步：执行两组正式对照

保持桥接窗口打开，在 MATLAB 执行：

```matlab
run_motor_link_r4;
```

程序先运行 `no_feedback`，再运行 `with_feedback`：

- 两组都从原模型初始状态开始，诊断 B 支路在模型时间 0.96 s 起加入 +0.2 A 偏移。
- 0.9 s 后才开始选择完整电周期。周期均值由 F4 用上传的 FP32 点计算。
- 第一组照常收集 NPU 结果和板端报警，但不修改参考。
- 第二组在板端本轮连续三周期同类异常确认后，才决定修改未来参考。
- 模型按 0.02 s 分段，回复到达时该段已经算完；处理在**下一模型采样点**开始，不能追溯到较早的周期结束时刻。
- 参考在 0.25 s 内降至零并锁存到本次 1.5 s 结束，不自动复位。
- 处理后的新模型电流会继续发给实板；低速、周期不完整或半周期频率变化超过 5% 时标为诊断条件不足，不把它当成正常恢复。

每个周期要上传几百个点并等待确认，现实中会花几秒；还有模型重新编译/恢复的等待。整个两组实验可能要十几分钟或更久，以实际运行进度为准，不要因为模型时间停在某一值就重复点运行。

失败时实验停止并保存 partial_results，不自动重试或改用本地分类。若发生超时，先停桥接窗口再检查，避免旧的在途结果被后续实验使用。

## 第五步：检查结果

结果保存到 `motor_link_r4\results\R4_时间戳\`：

- `status.json`：是否执行完成、是否满足本轮验收。
- `link_comparison.mat`：模型全量数组、原始周期点、真实返回和板端决策。
- `evidence.json`：方便独立复算的同一份证据。
- `link_comparison.png`：两组响应图。
- `action.json`：触发请求序号、板端 token、源周期时间、模型生效时间与现实等待时间。

预设验收条件：

1. 两组在处理生效前的转速最大差小于 0.001 rpm。
2. 两组均有本轮实板分类产生的确认报警。
3. 处理组参考降至零并保持。
4. 最后 0.1 s 处理组平均绝对转速不高于对照组的 20%，且对照组该均值大于 100 rpm。
5. 至少一个**完全在处理生效后产生的新电周期**再次经过实板 NPU。

不能因为弹出图就认定通过。需 `status.completed=true` 且 `status.passed=true`；再用 `tools/audit_run.py` 复核证据。该复核需要 NumPy：

```bat
python tools\audit_run.py "实际结果文件夹\evidence.json"
```

诊断偏移没有因为降速自动消失，因此不要求后续 NPU 变成 Normal。本版验证的是“本轮诊断触发处理，而且新数据再次参与诊断”。
